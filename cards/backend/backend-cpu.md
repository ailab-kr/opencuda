## 동작

연결 층 규격의 함수 26개를 CPU에서 구현한다. GPU 없이 정확성 시험을 돌리기 위한 기준 구현이다.

- 메모리: 256바이트 정렬, 모든 할당을 추적. 남의 포인터·중간 포인터·두 번 해제를 오류로 알림. 복사와 채우기는 할당 범위를 넘으면 오류.
- 대기열: 대기열마다 작업 스레드 하나. 넣은 순서대로 실행. 실행 인자는 제출할 때 복사.
- 표식: 기록한 적 없는 표식은 완료 상태. 다시 기록하면 앞선 기록은 무시. 대기열에 기록이 남아 있어도 해제 가능.
- 실행: GPU 스레드 하나가 파이버 하나. 블록 하나는 OS 스레드 하나에서 동기화 지점에서만 전환. 블록들은 여러 OS 스레드에 분산.

## 경계 조건

- 블록 크기 1024 초과, 축별 한도 초과, 0 크기, 공유 메모리 48KB 초과는 오류.
- 동기화 지점 전에 끝난 스레드는 도착한 것으로 친다. `OCU_CPU_STRICT=1`이면 오류.
- 커널 안에서 다시 실행을 요청하면 "지원 안 함".

## 시험 목록

`tests/backend/test_cpu_backend.c`: 16개 묶음, 기본 모드 164개 확인 항목. 세 모드(기본, 무작위 순서, 엄격·묶음 64·스레드 1개)로 실행.

- [x] 장치 조회, 메모리 범위·해제 규칙, 모듈 검증
- [x] 1차원 실행, 3차원 격자·블록 색인, 실행 한도
- [x] 동기화 지점(블록 합), 조기 종료, 스레드 순서(고정·무작위), 블록 간 원자 연산
- [x] 대기열 순서·동기화·조회, 인자 복사, 표식 시간 측정, 두 대기열 독립, 대기열 오류 보고
- [x] 묶음 단위 크기 설정

검증: 일부러 넣은 오류 4종(동기화 무효, 인자 미복사, 범위 검사 한 칸 오차, 표식 상태 누락)을 모두 잡음. 주소·정의되지 않은 동작·스레드 검사 도구에서 깨끗함(Clang 18).

- [x] 세 번째 독립 검토(11/12, 작업 스레드 묶음·등록부·드라이버·측정기): 도우미 스택 실패 시 바쁜 대기, `fork()` 뒤 교착·저하, 같은 호출 자리의 다른 반복을 못 잡는 워프 표식 등 8건. 검토자 재현 프로그램으로 확인: fork 교착 2/200 → 0/200, 바쁜 대기 CPU/벽시계 3.9 → 1.0, 반복 건너뛰기는 엄격 모드에서 실행 실패로 알림
- [x] 독립 검토(별도 세션, 11/12): 8건 지적, 4건 재현. 전부 고침. 회귀 시험 `tests/backend/test_cpu_regressions.c`(60개 확인 항목). 수정 전 코드에서는 첫 시험이 해제 후 사용으로 실패하고 인자 시험에서 프로세스가 죽음.

## 메모

- 같은 세션이 구현과 시험을 썼다. 개발 규칙(시험과 구현은 다른 세션)을 이 카드에서는 지키지 못했다. 다른 세션의 독립 검토로 보완했다(위).
- 남은 작은 문제: 엄격 모드로 블록을 중단할 때, 주소 검사기의 가짜 스택이 회수되지 않는다(누수, 검사 빌드에서만).
- 진짜 동시 실행에서만 나는 블록 안 경쟁 상태는 무작위 순서로도 다 잡지 못한다.
- 블록 안에서 다른 스레드를 기다리며 도는 코드(동기화 지점 없는 대기)는 끝나지 않는다. GPU에서도 보장되지 않는 동작이다.
