## 동작

연결 층 규격의 함수 26개를 CPU에서 구현한다. GPU 없이 정확성 시험을 돌리기 위한 기준 구현이다.

- 메모리: 256바이트 정렬, 모든 할당을 추적. 남의 포인터·중간 포인터·두 번 해제를 오류로 알림. 복사와 채우기는 할당 범위를 넘으면 오류.
- 대기열: 대기열마다 작업 스레드 하나. 넣은 순서대로 실행. 실행 인자는 제출할 때 복사.
- 표식: 기록한 적 없는 표식은 완료 상태. 다시 기록하면 앞선 기록은 무시. 대기열에 기록이 남아 있어도 해제 가능.
- 실행: GPU 스레드 하나가 파이버 하나. 블록 하나는 OS 스레드 하나에서 동기화 지점에서만 전환. 블록들은 여러 OS 스레드에 분산.
- 연산 표 GEMM(`cpu_gemm.c`, 11/13): 행 단위 기준 구현 대신 블록 루틴. 출력 타일(최대 64행 × 96열, 타일이 64개보다 적으면 더 잘게)마다 스레드 1개짜리 블록 하나로 실행해 대기열 순서와 묶음 스레드를 그대로 쓴다. 타일 안에서는 k를 512씩 나눠 A 행·B 열을 OS 스레드별 버퍼에 binary32로(f16·bf16은 여기서 변환, x86-64는 F16C) k 방향 연속으로 옮기고, 8폭 벡터로 4×3 내적을 한다. 누적은 binary32, 한 출력의 누적 순서는 스레드 수와 무관(k를 타일 사이에 나누지 않음). x86-64에서 AVX2·FMA·F16C가 있으면 그 판(`cpu_gemm_avx2.c`), 없으면 기본 판. `OCU_CPU_GEMM=ref|generic`으로 고를 수 있다.
- 블록 통째 반복문(11/13, `docs/cpu-region-loops.md` 1단계): 동기화 지점이 없는 커널은 컴파일러 패스(`compiler/cpu_loops`, LLVM 18 패스 플러그인)가 블록 하나를 반복문 한 번으로 도는 진입점을 더한다(모듈 이미지 판 2, 파이버 진입점은 늘 남김). 백엔드는 그 진입점을 블록의 파이버 하나(파이버가 처음 쓸 스택) 위에서 부르고, 고정 순서 또는 파이버의 첫 라운드와 같은 블록별 섞기 순서로 스레드를 돈다. 커널 포인터로 실행하는 자리는 포인터가 검사를 통과한 같은 형의 커널이 아니면 진입점이 거절하고 그 실행은 파이버로 돈다. `OCU_CPU_FORM=fiber|loop|dispatch`(기본 loop, dispatch는 지금 loop와 같음), `OCU_CPU_STATS`에 형태 열, `OCU_CPU_TRACE`(실행마다 전체 장치 메모리 해시). 패스가 없는 곳(Windows MinGW, 교차 빌드, LLVM 개발 파일 없음)은 모든 커널이 파이버.

## 경계 조건

- 블록 크기 1024 초과, 축별 한도 초과, 0 크기, 공유 메모리 48KB 초과는 오류.
- 동기화 지점 전에 끝난 스레드는 도착한 것으로 친다. `OCU_CPU_STRICT=1`이면 오류.
- 커널 안에서 다시 실행을 요청하면 "지원 안 함".

### 속도 작업(11/13)에서 시험 작성자가 확인할 동작

구현 세션이 쓴 목록이다. 시험은 다른 세션이 쓴다. 고정 순서·무작위 순서, 묶음 32·64, `OCU_CPU_THREADS=1`과 여러 개, 검사 도구 빌드와 일반 빌드 모두에서(일반 빌드에서만 도는 경로가 있다: 아래 3·4).

1. 워프 연산 한 번 기다림: 같은 워프가 셔플·투표를 연달아 수십 번 할 때 값이 매번 맞음(앞 연산의 값이 다음 연산에 새지 않음, 홀짝 두 칸). 빨리 끝난 레인이 다음 연산 값을 써도 늦은 레인이 앞 연산 값을 읽음.
2. 마지막에 도착한 레인이 전환 없이 계속 가도 불일치 검사(다른 호출, 다른 순번, 다른 마스크)가 그대로 실패로 알림. 엄격 모드에서 "이미 끝난 레인"과 "같은 연산을 마치고 끝난 레인"을 구분(겹치지 않는 절반 마스크 뒤 바로 `return`은 통과).
3. 고정 순서에서 스레드 시작 순서 0, 1, 2, ...가 그대로(끝난 스레드가 다음 스레드를 같은 스택에서 시작, 기다리는 스레드가 다음 준비된 스레드로 바로 넘김). 블록 동기화·워프 연산이 섞인 커널의 결과가 무작위 순서와 같음.
4. 스택: 기다림 없는 블록은 스택 하나만 씀. 스택 넘침은 스레드 1개 블록이 아니면 실패로 알림(가장 먼저 쓰는 스택이 맨 위 칸). 넘침을 알린 뒤 같은 모양의 다음 실행이 정상(카나리 복구). 스택 꼭대기 위치가 스레드마다 다름(64바이트 단위).
5. 새 함수 `ocu_cpu_warp_shuffle_masked`(범위 밖 `src`는 자기 값, 짧은 마지막 워프 포함)와 `ocu_cpu_warp_vote_masked`(없는 레인은 0): 모으기 결과와 같은 값. 언어 층의 `__shfl*_sync`(폭 1·2·4·8·16·32, 음수 `src`), `__ballot_sync`·`__any_sync`·`__all_sync`(마스크 0, 부분 마스크, 짧은 워프)가 이전과 같은 값.
6. `ocu_cpu_lane_id`·`ocu_cpu_warp_size`가 커널 안팎에서 맞음(밖에서는 설정값).
7. 묶음 스레드: `OCU_CPU_SPIN_US=0`과 기본값에서 결과 같음, 실행이 끝나면 CPU 사용이 0으로 돌아옴(지켜보기 뒤 잠듦), `fork()` 뒤 자식에서 실행 정상.
8. `OCU_CPU_STATS=1`: 끝날 때 한 줄 요약과 커널별 표를 표준 오류로, 꺼 두면 아무것도 안 냄.
9. x86-64 전환: MXCSR·x87 제어값을 바꾼 커널(반올림 방향)이 다른 파이버에 번지지 않고 각자 값을 유지.

### 블록 통째 반복문(1단계, 11/13)에서 시험 작성자가 확인할 동작

구현 세션이 쓴 목록이다(자세한 판은 `docs/cpu-region-loops.md` "Tests for an independent session"). 시험은 다른 세션이 쓴다. 모두 `OCU_CPU_FORM=fiber`와 `=loop` × 고정 순서·무작위 씨앗 여러 개 × 묶음 32·64 × `OCU_CPU_THREADS` 1과 여러 개에서, 결과를 비트까지(`OCU_CPU_TRACE`) 비교하고 형태는 `OCU_CPU_STATS`·`OCU_CPU_LOOPS_REPORT`로 확인한다. 구현 세션이 넣은 차분 시험(`cpu_forms_*`)은 기존 시험 프로그램을 두 형태로 돌릴 뿐이다.

1. 판정 골든 목록과 변이: 동기화 없는 커널은 loop. 호출 그래프 어디든 `__syncthreads`(직접, 도우미, 인라인 안 되는 함수, 커널 인자 조건 아래, `return` 뒤 죽은 코드), `__syncthreads_count/and/or`, 워프 함수 전부(`__shfl*_sync` 폭별, `__ballot_sync`, `__any/__all_sync`, `__syncwarp`), cub 블록·워프 원시 함수, 인라인 어셈블리, `fesetround`/`fesetenv`, 다른 번역 단위의 함수, 가상 호출, weak 장치 함수가 있으면 fiber이고 이유가 맞음.
2. 포인터 실행: `cudaLaunchKernel`, 커널을 매개변수로 받는 템플릿 도우미, `auto k = c ? k1 : k2; k<<<>>>`, 메모리에 둔 커널 포인터, 같은 형의 커널 중 하나만 동기화가 있을 때(그 커널은 실행 때 거절되어 파이버로, 결과 맞음, 통계 fiber 또는 mixed), 다른 번역 단위 커널의 포인터, 한 형의 커널 257개, 인자 복사 말고 다른 일을 하는 실행 람다.
3. 색인과 모양: 1·2·3차원 블록(3×5×7, 1×1×64, 1024×1×1, 1×1024×1, 1스레드), 블록 수백만 개, `threadIdx`/`blockIdx`/`blockDim`/`gridDim`/`warpSize`, `__activemask()`·`ocu_cpu_thread_idx`·`ocu_cpu_lane_id`를 부르는 커널, 짧은 마지막 워프.
4. 순서: 마지막 쓰기가 이기는 커널(`o[0] = threadIdx.x`)이 같은 씨앗에서 두 형태 같고 씨앗마다 다름, 스레드별 `printf` 순서, 동기화 없이 공유 메모리를 통해 순서에 기대는 커널.
5. 조기 return: 스레드 색인에 따라, 반복문 안에서, 모든 스레드가 곧바로, 쓰기 앞과 뒤.
6. 지역 변수와 스택: 스택을 거의 다 쓰는 지역 배열(`OCU_CPU_STACK_KB` 작게), 넘침이 두 형태 모두 실행 실패로 알려지고 다음 같은 모양 실행은 정상, 가변 길이 배열·`alloca`, 지역 변수 주소를 전역·공유 메모리에 쓰고 같은 스레드가 다시 읽기, 초기화 안 한 지역 변수(정의 안 된 동작: 죽지 않는지만).
7. 부동소수점 제어: 호스트가 실행 전에 바꾼 반올림·FTZ로 loop 커널의 모든 스레드가 시작하고 호스트 쪽 값은 그대로, 바꾸는 커널은 거절(fiber)되어 전과 같이 동작.
8. 메모리: 동적·정적 공유 메모리(블록마다 새로, 시작 0xA5), OS 스레드 여러 개에서 블록 사이 원자 연산, 고정·관리 메모리.
9. 엄격 모드(`OCU_CPU_STRICT=1`)와 `OCU_CPU_FORM=dispatch`: 기본과 같은 결과.
10. 컴파일: `-O0`(변환 없음), `-g`, `OCU_CPU_LOOPS=off`, 잘못된 `OCU_CPU_LOOPS` 경로(경고 후 파이버), 툴킷(`ocu-nvcc`)과 설치본이 플러그인을 찾음, `-ccbin g++`, 패스 있는 객체와 없는 객체를 함께 링크(같은 inline 커널을 양쪽에서 실행).

### 연산 표 GEMM 블록 루틴(11/13)에서 시험 작성자가 확인할 동작

기존 `ops_cpu`(`tests/ops/test_ops.c`)는 세 판(`OCU_CPU_GEMM` 없음·`generic`·`ref`) 모두 통과한다. 더 볼 것:

1. 모양 경계: M·N이 4·3·타일(64·96)의 배수가 아닌 것, K가 8·512의 배수가 아닌 것(1, 7, 513, 1025), M=1·N=1, 전치 네 가지, 행 간격 > 행 길이, 배치에서 A 또는 B 공유(크기 1), VAR_ROWS로 계획보다 적은 행.
2. 세 판의 결과가 GEMM 오차 등급 안이고, 같은 판에서 `OCU_CPU_THREADS` 1·8·24의 결과가 비트까지 같음.
3. beta 0에서 C의 NaN을 읽지 않음, alpha 0에서 A·B를 읽지 않음(NaN을 넣어 확인), A·B의 Inf·NaN이 결과에 퍼짐, f16·bf16 출력의 반올림(가장 가까운 짝수)과 넘침(무한대).
4. 대기열 순서: 같은 대기열의 복사·커널·다른 실행 사이에서 순서가 맞음.
5. 반정밀도 비정규수 입력(0x0001 등)이 정확히 변환됨(F16C 판과 기본 판 모두).
6. 큰 K(예: 4864)와 큰 배치에서 메모리(OS 스레드별 버퍼는 스레드가 끝날 때 해제, 주소 검사기로 누수 없음).
