# 보안 정책

[English](SECURITY.md) · **한국어**

> 검토용 초안.

## 취약점 신고

보안 문제는 공개 이슈로 올리지 않는다. 저장소의 비공개 취약점 신고 기능("Security" 탭, "Report a vulnerability")을 쓴다.
영향받는 버전이나 커밋, 플랫폼과 백엔드, 관찰한 내용, 재현 방법을 함께 적는다.

신고를 받으면 영업일 기준 [3]일 안에 접수를 알리고, [10]일 안에 평가를 전하며,
신고일로부터 [90]일 안에 수정과 보안 공지를 낸다. 이름을 밝히기를 원하는 신고자는 공지에 올린다.
이 기간 안에서 조율된 공개를 요청한다.

## 지원 버전

첫 안정 출시 전에는 main 브랜치의 최신 커밋만 지원한다. 출시 후에는 최신 출시본과 그 직전 출시본에 보안 수정을 낸다.

## 범위

범위에 포함되는 것:

- 실행 API 구현, 백엔드, 라이브러리, 컴파일러 연결부의 메모리 안전 오류
  (범위를 벗어난 복사, 해제 후 사용, 크기 계산의 정수 넘침, API를 통과하는 검사 안 된 포인터);
- 백엔드 로더와 등록 코드. 벤더 드라이버 라이브러리를 실행 중에 불러오는 부분을 포함한다;
- 변환기와 코드 생성기. 조작된 입력으로 자기 출력이 아닌 것을 실행하거나 쓰게 만들 수 있는 경우;
- 믿을 수 없는 결과 기록을 처리하는 점수판과 적합성 시험 도구.

범위에 포함되지 않는 것:

- 칩 벤더의 드라이버나 라이브러리의 취약점. 벤더에 신고한다(신고 전달은 돕는다);
- 사용자가 넘긴 임의의 코드를 CPU 백엔드가 실행하는 것. 설계상 커널을 호출한 프로세스의 권한으로 실행한다;
- 일부러 끝나지 않게 만든 프로그램에 의한 서비스 거부.

## 이미 적용한 강화 조치

빌드는 주소, 미정의 동작, 스레드 새니타이저로 시험한다. CPU 백엔드의 커널 스택에는 보호 페이지와 넘침 감지가 있다.
GPU 백엔드의 메모리 표는 범위를 벗어난 복사와 할당 중간 지점의 해제를 드라이버에 넘기지 않고 거부한다.
